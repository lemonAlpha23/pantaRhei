# Panta Rhei

一个本地优先的中文桌面行情工作台，支持沪深 A 股看盘、自选股报价监控、价格提醒、同屏多图对比、板块热力图和财经资讯。行情、自选、提醒规则和触发记录保存在本机的 SQLite 数据库中。

## 开始使用

Windows 构建的安装程序位于 `release/`。安装后打开 **Panta Rhei**，Python 行情服务会随桌面应用一起启动。

1. 在行情页查看贵州茅台，或点击右侧自选股切换标的。
2. 按 **Ctrl+K**（macOS 使用 **⌘K**），按名称、代码或行业搜索本地股票。输入完整的六位沪深 A 股代码，可联网查找并导入其他股票。
3. 点击股票旁的星标保存自选。点击「更新行情」获取日线，股价下方显示最后一个交易日，交易概况列出日内区间、数据来源和复权方式。
4. 在图表上切换日 K 线与收盘价折线，调整区间，或分别开关 MA5、MA20 和成交量。移动十字光标可查看对应交易日的价格。
5. 打开「资讯」查看按上海时间排列的财经标题。首次进入时联网获取，之后优先显示本地记录。可按来源筛选、点击「刷新」更新，或点击标题在默认浏览器阅读原文。
6. 打开「对比」并排查看最多四只股票的日 K 线。顶部切换共同的交易日区间，每张图可替换标的。区间涨跌幅按首末交易日的收盘价计算，缺少端点行情时会在图中说明。
7. 在桌面版点击顶栏右侧的「在新窗口打开」图标，将当前页放到独立窗口。行情窗口会带上股票、图区间和指标，对比窗口会带上组合与区间，自选和资讯会带上当前排序或来源。随后可分别切换页面和标的，关闭最初的窗口后，其余窗口仍可使用。
8. 打开「板块」，在本地股票库或自选股中查看行业表现。方块面积代表当日报价的股票数，颜色代表有涨跌幅数据的股票的等权平均表现。选中方块可查看成分股，点击股票可进入其行情页。
9. 打开「监控」查看自选股的最新报价和涨跌幅。页面可见时每轮更新结束后等待 30 秒再刷新，可暂停或点「立即刷新」。点股票名称可进入行情页，在新窗口打开时会带上当前的暂停状态。
10. 打开「提醒」，选择本地股票库中的股票，设置「达到或高于」或「达到或低于」及目标价。工作台运行时会自动检查，切到其他页面也会收到应用内提示。达到条件后规则暂停，可手动重新启用。「触发记录」显示触发时的报价及行情源时间。

11. 打开「X 动态」，添加博主的 @用户名，点「立即同步」建立首次快照。之后可以按博主或「交易线索」筛选，点「原帖」核对原文。
12. 在「监控博主」中为重点账号选择「只提醒下单」或「提醒所有买卖」。下次同步到符合条件的新帖时，行情页等工作台页面会显示作者、方向和标的。点「查看原帖」核对消息，或点「提醒记录」逐条处理未读。
13. 打开「X 动态 → 连接与投递」，在「连接配置」分别保存、测试 X API 与 Webhook，在「投递记录」按状态筛选、查看每次尝试，并手动重试失败事件。
14. 在「行情 → 日 K」图表下方打开「博主下单标记」，就能在当前股票的日线上回看已监控博主公开披露的委托。开关默认关闭，选择会在本机记住。

## 从源码运行

开发需要 Node.js 22.12 以上、pnpm 10 和 uv。uv 按项目配置准备 Python 3.12。首次安装依赖需要联网。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

| 命令 | 用途 |
| --- | --- |
| `pnpm dev` | 通过 electron-vite 开发模式启动 Electron，支持主进程重启和 Vue 热更新 |
| `pnpm dev:web` | 在终端输出的本地地址预览界面，使用独立的预览数据库 |
| `pnpm test` | 验证插件安装与迁移、行情与资讯、图表对比、IPC 及服务生命周期 |
| `pnpm build` | 检查 TypeScript 类型，通过 electron-vite 构建主进程、预加载脚本和 Vue 渲染器 |
| `pnpm package` | 冻结 Python 服务，构建当前系统的桌面安装包到 `release/` |

自动化验收使用 `pnpm test` 和 `pnpm build`，界面检查使用无头浏览器。仅在手动使用应用时运行 `pnpm dev`。electron-vite 会在开发启动和打包前检查生成的主进程及预加载脚本，构建阶段即可发现装饰器未转译等语法错误。

## 行情与存储

内置 12 只股票，每只包含 2024-04-08 至 2026-11-25 的 640 个交易日。快照采用腾讯自选股前复权日线，人民币计价，成交量统一为股。首次启动即可离线查看。联网导入和更新只保存已收盘的交易日。均线按历史序列计算，切换可见区间不会截断均线的计算窗口。

沪深股票的交易日按 `Asia/Shanghai` 判断。更新优先获取腾讯日线，腾讯历史接口不可用时会尝试新浪财经的不复权日线。每次使用同一来源的完整序列，并一起保存行情源、复权口径和最新交易日。内置标的和采集时间见[行情快照目录](apps/backend/app/plugins/market/snapshots/catalog.json)。

桌面版使用 Electron 用户数据目录下的 `data/workspace.sqlite3`。Windows 通常位于 `%APPDATA%\Panta Rhei\data\`。网页开发预览使用 `~/.pantarhei/preview/`。两种入口的自选股互相独立。

同一桌面工作台的窗口共用一个本地服务和数据库。在任一窗口修改自选、导入股票、更新行情或刷新资讯后，其他相关窗口会重新读取已保存的数据。各窗口分别保留正在查看的股票与筛选条件。

监控页按自选列表批量获取腾讯报价，涨跌幅按最新价相对昨收计算。每行的报价时间取自行情源，以上海时间显示。「最近检查」记录工作台访问行情源的时间。休市、停牌或来源延迟时，两者可能相隔较久。获取失败的股票保留上次成功报价，首次获取前显示空值。盘中报价单独存储，K 线、技术指标和板块热力图继续使用收盘日线。

价格提醒由本地服务每轮检查完毕后等待 30 秒再检查，按已启用规则中的股票取价。可以为非自选股建规则。报价时间须在规则启用当秒或之后，距检查时间不超过 5 分钟，同一规则每个报价时间只判断一次。触发后，实际价格、目标价和报价时间同时写入 SQLite。离线期间规则保持启用，退出应用后停止检查，下次启动时继续。删除规则会保留历史，界面列出最近 100 条。

板块热力图使用每只股票最新保存的报价。日期选项来自当前股票池的报价日期，每只股票只计入其报价所属日期。缺少前收盘价的股票计入面积，计算平均涨跌幅时跳过。内置股票按快照行业归类，缺少行业信息的股票归入「未分类」。

资讯来自两家媒体的官方 RSS。应用为每个来源保留最近 100 条标题、发布时间与原文地址。单个来源更新失败时，其他来源可正常更新，已有标题仍可离线查看。阅读全文需要联网。[中新网财经](https://www.chinanews.com.cn/rss/finance.xml) · [经济观察网](https://www.eeo.com.cn/rss.xml)

### X 博主监控与外部 API

应用内提醒默认关闭。「只提醒下单」匹配博主明确披露的已提交委托，「提醒所有买卖」还包含博主自述的买入、卖出。首次同步建立基线，切换提醒范围从设置生效后开始计算。使用本地提醒只需配置 X 数据源；Webhook 可独立选择是否启用。

提醒记录及已读状态保存在 SQLite，所有窗口共用。打开提醒中的原帖成功后，该条自动标为已读，也可手动逐条或全部标记。收起提示条或进入记录页会保留未读状态。列表每次优先显示未读，最多 100 条；未读总数统计全部记录。退出重启或移除博主后仍可查看已保存的记录。

数据源使用 X 官方 API v2，按用户名查找账号，再增量读取其公开时间线。工作台运行时每轮同步后等待 5 分钟，后台处理分页和限流。首次获取最近一页，恢复订阅时重新建立基线。订阅和帖子保存在 SQLite，页面显示最近 200 条。移除博主会保留已同步的帖子。[用户名查询](https://docs.x.com/x-api/users/get-user-by-username) · [用户时间线](https://docs.x.com/x-api/users/get-posts)

日 K 标记只读取本地 SQLite 中当前启用博主对这只沪深 A 股披露的委托。买单用向上箭头，卖单用向下箭头，同日同方向的多条披露合并计数。点击对应 K 线或从图下选择日期，可查看每条披露的博主、发帖时间、委托价和数量。标记按上海时间对应到发帖日，发帖日缺少日 K 时保留在动态里。选中日期后，不复权图上会用圆点标出原帖明确以人民币披露的委托价。披露记录只代表博主的公开表述，交易所的成交时间和成交价需要成交回报确认。

在「X 动态 → 连接与投递 → 连接配置」填写 X Bearer Token、可选的 HTTPS 接收地址和接收端令牌。每组可独立保存，即时生效。页面显示配置来源和接收主机。Windows 使用当前用户的 DPAPI 加密后保存到 SQLite。macOS 和 Linux 分别使用钥匙串和 Secret Service 保管工作区的加密密钥。已有环境变量继续有效，点击「移除本机值」并保存，可恢复使用相应环境配置。更换接收地址时，如需鉴权，应同时填写该地址使用的令牌。

点击「测试连接」会使用已保存的有效配置。X 测试查询公开账号 `@X`，用于确认账号查询权限；同步帖子还需时间线读取权限。Webhook 测试会发送一条独立的 `x.connection_test` 事件，成功时显示接收端的 HTTP 状态。接收端可按事件类型与正式交易线索分别处理。[X 开发者平台](https://developer.x.com/) · [Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)

也可使用下列环境变量，改动环境变量后需重新启动工作台。

| 环境变量 | 用途 |
| --- | --- |
| `PANTARHEI_X_BEARER_TOKEN` | X 开发者应用的 Bearer Token，用于同步博主帖子 |
| `PANTARHEI_X_WEBHOOK_URL` | 可选，接收新交易线索的 HTTPS POST 地址 |
| `PANTARHEI_X_WEBHOOK_TOKEN` | 可选，接收方指定的独立 Bearer Token |

插件识别中英文帖子开头明确、自述的单标的买卖或已提交委托。例如「我已提交限价卖单：600519 100 股，委托价 1500 元」会标为博主披露的限价委托。「I bought 10 shares of $AAPL at $180.50.」会标为自述买入。这些字段来自公开文字，实际订单状态和成交结果须由授权券商接口核实。图片、含糊表述和复杂多腿交易可打开原帖查看。

配置 Webhook 后，首次基线以后的新线索会写入本地投递队列。公开文字保留在工作台，发送的事件只包含结构化字段、来源和原帖地址。以下为虚构示例。

```json
{
  "schemaVersion": 1,
  "event": "x.trade_signal",
  "eventId": "x:post:123",
  "source": "x_public_post",
  "handle": "demo",
  "postId": "123",
  "url": "https://x.com/demo/status/123",
  "publishedAt": "2026-11-26T02:00:00.000Z",
  "signal": { "kind": "order", "orderType": "limit", "action": "sell", "symbol": "600519", "price": 1500, "quantity": 100 }
}
```

其中 `kind` 为 `order`（作者称已下单）或 `trade`（作者自述买卖）。委托类型、价格或数量缺失时为 `null`。接收端应按请求头 `Idempotency-Key` 或同值的 `eventId` 去重，成功处理后返回 2xx。超时或失败会在后续同步时重试，应用重启后恢复队列。每条待发任务绑定创建时的接收地址，暂停或移除博主会取消尚未发出的任务。

「投递记录」支持按待投递、已送达和失败筛选。展开「详情」可查看新版本记录的每次尝试、上海时间、HTTP 状态或连接错误。排查接收端后，点该行的「重试」会立即向原地址发送同一事件，沿用原幂等键。订阅已取消、地址已变更或仍在投递时，页面会说明原因。旧版已保存的状态和次数会保留，逐次详情从本版升级后开始记录。

接口输出采用固定 JSON 结构，参考了 catbus 的统一输出方式。X 账号鉴权交给官方开发者接口，插件沿用工作台已有的 Python 和 SQLite。[catbus](https://github.com/cv-cat/catbus) · [XApis](https://github.com/cv-cat/XApis)

## 工程结构

本仓库将桌面端和后端分别放在 `apps/desktop` 和 `apps/backend`。根目录 `package.json` 提供整个仓库的开发、测试与打包命令。Electron 和 Vue 的依赖在 `apps/desktop/package.json`，Python 服务的依赖和测试配置在 `apps/backend/pyproject.toml`。

| 目录 | 职责 |
| --- | --- |
| `apps/desktop/main`、`preload` | 创建桌面窗口、管理 Python 服务生命周期，通过受限 IPC 访问本地 API |
| `apps/desktop/renderer/src/core/` | 工作台布局、导航、页面缓存及共享 HTTP 传输 |
| `apps/desktop/renderer/src/plugins/` | 桌面端启用的前端插件清单，每个业务包维护自己的 Vue 页面、状态和 API 适配器 |
| `apps/backend/app/core/` | 本地服务生命周期、鉴权、健康检查、SQLite 连接与插件迁移 |
| `apps/backend/app/api.py` | 选择并组装桌面版启用的插件 |
| `apps/backend/app/plugins/market/` | 行情、自选、提供者、离线快照及其存储与路由 |
| `apps/backend/app/plugins/alerts/` | 价格提醒规则、后台报价检查与触发历史 |
| `apps/backend/app/plugins/xmonitor/` | X 公开时间线、交易线索解析与 Webhook 投递队列 |
| `apps/backend/app/plugins/news/` | 订阅获取、标题聚合、资讯缓存及其存储与路由 |

桌面端使用 TypeScript，通过 `apps/desktop/electron.vite.config.ts` 统一配置三个入口。Vue 组件使用 `<script setup lang="ts">` 和箭头函数，组件样式写在同文件的 `<style scoped lang="scss">` 中。共享主题保存颜色、字号和通用控件样式。界面以 Coinbase 风格的白底与蓝色操作控件为基础，行情沿用 A 股的红涨绿跌。[设计参考](DESIGN.md)

Electron 通过标准输出获取后端实际绑定的回环端口，以每次启动生成的令牌访问 API。关闭应用时，管道关闭会通知 Python 服务退出。

主进程在应用就绪后注册标有 `@BindMapping('market')` 的行情控制器。以读取日线为例，渲染器调用 `getHistory(symbol)`，预加载脚本转发到 `market:getHistory`，主进程验证发送方后按共享契约访问 FastAPI。行情操作的参数、返回值和 HTTP 路径统一在 `apps/desktop/shared/market.ts` 定义。装饰器的命名与控制器组织参考了 [RuoYi-Geek-Electron](https://github.com/Geek-XD/RuoYi-Geek-Electron/blob/0fe6c826bacd512929ef0661c3cc174b889b933d/src/main/annotation/BindMapping.ts)。

资讯控制器使用 `@BindMapping('news')`，通过 `apps/desktop/shared/news.ts` 约定读取、刷新和打开原文三个操作。打开原文时，渲染器传入文章编号，本地服务从缓存中查找并校验媒体原文地址。

### 添加前端插件

在 `apps/desktop/renderer/src/plugins/` 下建立业务目录，把 Vue 页面、相关组件和状态放在一起。在该目录的 `index.ts` 导出插件描述，再把它加入[前端插件清单](apps/desktop/renderer/src/plugins/index.ts)。导航按清单与页面的声明顺序生成，首个页面就是首页。

下面展示一个已有 `NotesView.vue` 的笔记插件入口。

```ts
import type { WorkbenchPlugin } from '../../core/workbench'
import NotesView from './NotesView.vue'

export const notesPlugin = {
  id: 'notes',
  pages: [{ id: 'notes-list', label: '笔记', component: NotesView }],
} satisfies WorkbenchPlugin
```

插件可用 `layout` 为自己的页面提供加载及重试界面，用 `toolbar` 把操作放入工作台顶栏。行情插件将看盘、自选和多图对比组合在一起，共享股票库和搜索。资讯插件为页面声明 `keepAlive: true`，切换页面时保留来源筛选。插件需要访问本地服务时，沿用 `apps/desktop/shared/` 的类型契约，通过现有预加载桥接或网页预览适配器调用。

每个已注册页面都可在独立窗口打开。页面如需传递视图状态，可在 setup 中调用 `usePageWindowState(capture, title?)`。工作台在打开新窗时调用 `capture` 获取简短的字符串键值对，目标页首次挂载时从该函数的返回值恢复并校验状态。可选的 `title` 用于在任务栏区分不同窗口。状态只携带股票代码、区间或来源等视图参数，业务数据通过本地 API 读取。窗口管理和预加载桥接由工作台统一处理。

### 添加后端插件

1. 在 `apps/backend/app/plugins/` 下新建 Python 包，将该功能的路由、服务、数据访问与测试所用的独立入口放在一起。插件可从 `app.core` 引入公共接口。
2. 导出一个 `Plugin(name=..., register=..., migrations=...)`，给插件取一个稳定的名字。核心将 FastAPI 应用与 `Database` 传给 `register(app, database)`，通过 `app.include_router(...)` 接入的 API 会沿用工作台的会话鉴权。
3. 插件需要表结构时，在自己的 `migrations` 元组末尾追加 `Migration(迁移函数)`，每个函数接收 SQLite 连接。核心在同一事务里执行待应用的迁移并按插件记录版本。任一步失败会回滚，下次启动可重试。
4. 将插件加入 `app/api.py` 的组合清单，即可随桌面服务启动。开发和测试时可用 `create_application((plugin,), data_dir=...)` 单独挂载。临时移出插件会保留其数据，下次启用时可继续使用。

最小插件及其迁移、停用和重新启用的可运行示例见[插件回归测试](apps/backend/tests/test_plugins.py)。
